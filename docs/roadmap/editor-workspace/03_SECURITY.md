# 工作区安全边界

## 授权模型

工作区根路径来自 Tauri 原生目录选择器，并由 Rust `WorkspaceRegistry` 记录为规范目录。后续目录列举与新建命令必须使用该授权根目录；没有打开工作区时，命令返回错误。路径只用于目录树元数据和新建空 Markdown，不等于授予读取任意文件内容。

## 路径和链接

- 根目录必须是绝对路径、实际目录，所选目录本身不能为符号链接。
- 子目录请求必须位于规范工作区根目录内；拒绝 `..`、绝对越界路径和路径链上的符号链接。
- 目录扫描对 symlink 条目直接跳过，不跟随到外部目录或文件。
- `.git`、`.svn`、`.hg`、`node_modules`、`target`、`.next`、`.cache`、回收站/系统卷目录以及隐藏目录过滤。
- 目录扫描仅返回目录及扩展名识别出的 `.md/.markdown/.pdf/.ofd` 文件；不读文件正文。

## 资源和性能限制

- 采用逐层列举，不进行全树递归；每个目录最多回传 2,000 条，超出时标记截断。
- 前端只在展开时加载子目录，缓存已加载层；刷新根和已展开层。
- 超大目录仍由系统文件枚举读取该层，但 IPC 返回条目数有上限；未实现增量分页。

## 新建文件

- 文件名只能是单个路径组件，不接受 `/`、`\\`、控制字符或 Windows 保留设备名。
- 扩展名只能是 `.md/.markdown`；未输入扩展名时追加 `.md`。
- 用 `OpenOptions::create_new(true)` 排他创建，避免覆盖竞态和旧文件内容损坏。
- 新建空文件后交给现有只读 Markdown reader 打开。编辑和写回仍未实现。

## 风险边界

- 外部进程可在授权检查与目录操作之间并发重命名/替换目录；当前标准库路径接口不是基于目录句柄的原子沙箱。若工作区需要抵抗恶意本地并发进程，应在 P4 评估平台专属 `openat`/`O_NOFOLLOW` 等句柄式实现。
- 目录选择不会持久化授权路径；重启后用户需重新选择。路径/展开状态恢复规划在 P4。
- 不向外部服务上传文件名、路径或内容；目录信息只在本机 UI 和本地 IPC 中使用。
