# MdStudio P6-B OFD 已知限制

当前 P6-B 状态：`blocked`。以下限制仍需通过有许可的样本、上游能力或新的获批实现范围解决；诊断入口只帮助用户看见降级，不会自动修复渲染引擎缺陷。

## 阶段阻塞

1. **无应用内中文最终兜底字体。** 现有字体功能只匹配本机系统字体；“思源黑体/思源宋体”是系统候选偏好，不是安装包内字体。系统没有目标字形时无法保证中文显示。字体资产许可来源仍待确认。
2. **样本矩阵不足。** 当前仓库只有一份发票 OFD，没有随库授权记录；缺少多页公文、票据、内嵌字体、竖排/旋转文字、A4/A5/自定义页面、复杂透明图层、JBIG2 和可对照的损坏容器样本。
3. **JPEG Viewer 缺陷历史未复测/未修复。** 旧 POC 记录 Viewer UI 在双页 JPEG 样本报“渲染已取消”并空白；旧样本不在当前工作树，当前没有可重复最小复现。不得将 Engine Canvas 成功等同生产 Viewer 成功。
4. **JBIG2/TIFF 插件未接入生产 Viewer。** Engine API 接收 `imageDecoders`，当前 UI 0.1.7 的 React options 没有公开透传该参数。修改第三方包内部、fork 或将生产阅读器换为手工 Engine Canvas 都不属于本轮最小宿主适配。
5. **字体缺失警告尚未闭环。** macOS 发票曾出现 Font 28/4 的 `W_FONT_MISSING`。字体候选不是逐文本对象映射，无法证明没有少数字符被跳过。
6. **版式和印章仅有限历史观察。** 发票签章轮廓被观察到，但没有可信参考阅读器图像；没有验证位置、尺寸、透明度、图层顺序、签名密码学有效性。应用只显示“未验证”。
7. **跨平台和性能数据不全。** Windows/Linux 未构建或实测；本轮未测大文件耗时、峰值内存、连续开关文档后的资源曲线。当前画布/cache 限额是代码配置，不是性能验收数据。

## 图像和引擎边界

- Engine 0.1.7 类型声明写明 PNG/JPEG 由宿主解码，JBIG2/TIFF 需 `ImageDecoderPlugin`。当前 Viewer UI 没有公开插件属性，因此不能单独在 MdStudio 外层增加这些解码支持。
- 引擎 warning 码由 `onWarning` 回调到达宿主，但 warning 只表示引擎检测到问题，不代表页面其他元素有问题；未知 warning 保留代码供定位。
- 当前诊断 UI 最多显示 100 条结构化 warning/error，额外数量会明确统计；同类事件按 code/message/page 去重，防止复杂文档把列表无限撑大。
- 英文/日文版为避免将第三方中文消息冒充翻译，会以本地化摘要和引擎代码呈现已知/未知 warning；中文界面可查看本地资源警告文本。不会把完整文档内容写入日志或上传。

## 建议的解除条件

- 将每份样本的来源、许可、脱敏方式、SHA-256 和参考阅读器/截图记录到矩阵。
- 加入有许可的字体 fallback 资产后再测试 bundle 体积、license notice、TTC/OTF 引擎兼容和缺字覆盖；不可从当前操作系统私自复制字体。
- 向 OFDRW 确认并取得稳定的公开图像解码器透传接口，或单独评审独立 Engine 适配；以 JPEG 空白样本和 JBIG2 文件作为准入 fixture。
- 在 macOS 与 Windows 至少对相同 OFD 样本进行分页、搜索、深浅主题和截图对照，并做打开/关闭压力及峰值内存测量。
- 对实际未显示文本建立对象/页码级最小复现，再决定上游 issue 或宿主修复；不可用“主体大致可见”代替文字完整性验证。
